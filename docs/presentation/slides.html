The model

A simple, fast model that gets 97.34% right

TF-IDF turns words and letter patterns into numbers; Logistic Regression picks the category. Trained on 10,519 messages (Banking77 plus generated loan queries), tested on 3,192 messages it never saw.

What we changed

A bulk engine: big file in, routed CSV out

The file is processed in the background, in large chunks, by every CPU core at once.
1
Upload once
The file becomes a background job. You get a job id and can follow progress.
2
Chunks of 20,000
Read from disk 20,000 rows at a time, so the file is never fully in memory.
3
One pass per chunk
Text features computed once; category and topic both use them.
4
Rules on the whole chunk
Rules run as array maths (NumPy). A test proves the decisions are exactly the same.
5
8 parallel workers
One process per CPU core; each loads the model once.
6
CSV + live samples
Results download as CSV. Each chunk sends 6 real routed rows to the screen.
Where the speed comes from
Features once, not twice
Array maths per chunk, not per message
8 cores instead of 1

Conclusion

Keep TF-IDF for traffic; add decision models where they help

1Why TF-IDF stays

  • Five fixed teams and plenty of labelled data: the right tool.
  • Fast: seconds for 1,000,000 messages, not days.
  • Small: 27.6 MB on any CPU, vs 808 MB with a GPU recommended.
  • Explainable: shows the words behind each decision.

2Why decision models still matter

  • New teams or new questions at request time, without retraining: just add an option.
  • Several decisions in one pass: team, urgency, “is the customer threatening to leave?”, “is a refund requested?”.
  • Calibrated probabilities: it can abstain and say “not sure”.
  • 100+ languages with its multilingual checkpoint.

3Next steps

  • TF-IDF handles the bulk of traffic.
  • A decision model as a second opinion only on the small share of low-confidence messages, where its time cost is affordable.
  • Fine-tune a transformer on our data next, for a fair comparison.
Honest limit1,000,000 messages in a file is not 1,000,000 users at once. That would need several servers, a load balancer and a queue.
